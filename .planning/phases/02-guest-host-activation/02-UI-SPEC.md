# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Surfaces covered: `/play` (`QuickStartView.vue`), `DeckImportPanel.vue` (reused by
`FormCreateGame.vue` and `JoinGameView.vue`), the unresolved-card correction UI, commander
review/selection (including partners/backgrounds), the optional display-name field, the four
D-2.13 recoverable failure states, and the sub-768px heads-up notice. `BoardView.vue` and
anything past arrival on `/games/:id` are out of scope (Phase 4 / ACT-011).

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Vue 3 SFCs (scoped SCSS reading CSS custom properties from `:root` in `app/src/styles/main.scss`) |

interop layer, which would be a strictly worse outcome than the existing hand-rolled
component pattern. The initialization question was not asked; `Tool: none` is recorded
directly. Registry safety gate: not applicable (see `## Registry Safety` below).

**Reuse mandate.** Every new component in this phase must read color from the existing
`--vedh-*` custom properties and reuse the existing `button.primary` / `button.secondary` /
`button.link` visual treatment verbatim (see `## Color`). Do not invent a second button
visual language for `/play`.

## Responsive Architecture

This is the highest-leverage decision in this contract — D-2.10 makes this phase's activation
components the first `@media`-driven responsive surface built to a deliberate architecture in
this codebase, and Phase 4's ACT-011 (board responsiveness) inherits whatever shape it takes.

**Correction to the research record:** `02-RESEARCH.md` states the codebase has "zero
`@media` queries." That is not accurate — three exist today (`LandingView.vue:702`,
`BoardView.vue:2646`, `GamesView.vue:319`), all `@media (max-width: …)` descending,
desktop-first, ad hoc per-component breakpoints (720px and 900px) with no shared variable and
no documented rationale. **This does not change D-2.10's decision.** What D-2.10 actually
establishes is new regardless: a single, ascending, mobile-first `min-width` breakpoint at a
named value, backed by one shared source of truth, scoped deliberately to a named set of
components. The three existing queries are a different, older, undocumented pattern and are
explicitly **not** to be extended, merged with, or reconciled against this phase's pattern.

**Breakpoint:** `768px`, `min-width`, exactly one query per component. Mobile-first: base
(unqualified) styles target the phone case (<768px); the `@media (min-width: 768px)` block
layers on tablet/desktop layout.

**Mechanism and single source of truth.** CSS custom properties cannot be referenced inside
an `@media` condition without a PostCSS custom-media plugin, and none is installed in this
Vite + `sass` build. Use a **shared SCSS variable file** instead:

```scss
// app/src/styles/breakpoints.scss (NEW)
$breakpoint-tablet: 768px;
```

Every new activation component's `<style scoped lang="scss">` block imports it the same way:

```scss
@use '@/styles/breakpoints' as bp;

.quick-start-layout {
  display: grid;
  grid-template-columns: 1fr; // phone: stacked
}

@media (min-width: bp.$breakpoint-tablet) {
  .quick-start-layout {
    grid-template-columns: 1fr 1fr; // tablet/desktop: two-column
  }
}
```

**Scope — applies only to:** `QuickStartView.vue`, `DeckImportPanel.vue`,
`CommanderReview.vue` (new), and the mobile heads-up notice component. Does **not** apply to
`FormCreateGame.vue`'s or `JoinGameView.vue`'s surrounding chrome (game name / deck size /
format fields, modal frame) — those wrap the new `DeckImportPanel` but are themselves
out of this phase's responsive scope and keep their current non-responsive layout.

**Layout behavior below 768px (phone, D-2.11 — works, no hard bounce):**
- Single-column stack: heads-up notice → deck import (paste/URL tabs) → preview
  totals/warnings → unresolved-card correction list → commander review → display name →
  primary CTA.
- The heads-up notice renders once, above the import tabs, non-dismissible, styled as
  informational (secondary-surface background, body text color) — never the accent or
  destructive color, since it is expectation-setting, not a warning or an error.

**Layout behavior at ≥768px (tablet/desktop, D-2.10):**
- Two-column option where it earns its keep: `DeckImportPanel`'s paste/URL input on the
  left, live preview totals/warnings on the right, updating as the user types/pastes.
  `CommanderReview` may lay candidate chips out as a wrapping grid rather than a single
  stacked list.
- The heads-up notice is not rendered (viewport is wide enough that the board disclaimer
  does not apply).

**Precedent note for Phase 4 (ACT-011):** extend `app/src/styles/breakpoints.scss` with any
new tokens (e.g. a desktop-only breakpoint) rather than creating a second source of truth;
reuse `$breakpoint-tablet` unchanged for `BoardView.vue`'s own responsive work.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inline padding |
| sm | 8px | Compact element spacing (label-to-input gap) |
| md | 16px | Default element spacing (form field stack gap) |
| lg | 24px | Section padding (panel/card padding) |
| xl | 32px | Layout gaps (between funnel steps on tablet/desktop) |
| 2xl | 48px | Major section breaks (`/play` page top padding) |
| 3xl | 64px | Page-level spacing (rare; only if `/play` needs a hero-style top gap) |

Exceptions:
- **44px minimum** hit target for any icon-only interactive control (chip remove `×`, modal
  close `×`, notice dismiss if one is ever added) — applies at every width, not only <768px.
- Existing embedding chrome in `FormCreateGame.vue`/`JoinGameView.vue` (game name, deck size,
  format fields, modal frame padding) is **not** retrofitted to this scale this phase — only
  the newly-built `DeckImportPanel`/`CommanderReview`/`QuickStartView` content follows it
  strictly.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Exactly two weights (400, 600) — matches the codebase's existing practice (`font-weight: 600`
is already the only non-default weight used for buttons, chip text, and hints across
`FormCreateGame.vue`/`JoinGameView.vue`; the loaded 500/700 font files are not used by this
phase's new components).

**Usage map:**
- **Display (28/600):** the `/play` page-level heading (e.g. "Paste a deck. Start a table.").
- **Heading (20/600):** per-step section headings inside the funnel ("Import your deck",
  "Choose your commander", "You're almost at the table").
- **Body (16/400):** paragraph copy, preview totals line, help text, error/failure body text.
- **Label (14/600):** form field labels, chip text, badge/pill text, the mobile heads-up
  notice text.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#3a3431` (`--vedh-bg`) | Page background behind `/play` |
| Secondary (30%) | `#4a423f` / `#544b47` (`--vedh-surface` / `--vedh-surface-strong`, panel variants `--vedh-panel` / `--vedh-panel-strong`) | Import panel card, preview totals card, commander-review card, heads-up notice background |
| Accent (10%) | `#f2a041` (`--vedh-primary`) | See reserved-for list below |
| Destructive / Error | `#e5484d` (**new token**, add as `--vedh-danger` to `main.scss` `:root`) | Blocking-error text/badges, the four D-2.13 failure banners |

Accent reserved for (explicit — nothing else may use it):
1. The single primary CTA button at each funnel step ("Preview deck", "Continue to
   commanders", "Start my table") — reuses the existing `button.primary` /
   `--vedh-primary-gradient` treatment verbatim.
2. The selected-state highlight on a chosen commander chip/card in Commander Review.
3. The "use nearest match" one-tap accept affordance on an unresolved-card suggestion row
   (the fast-path fix, distinct from the slower manual-search fallback).
4. Focus-visible outline on interactive form controls (consistent with the existing
   `a { color: var(--vedh-primary) }` link convention).

No destructive **actions** exist in this phase's scope (nothing is deleted or permanently
lost — a discarded paste can always be re-pasted, and `sessionStorage` draft state per D-2.12
is cleared only on success). The `--vedh-danger` token therefore has one job this phase: give
the four D-2.13 failure classes and blocking-card errors a color distinct from the accent, so
"something needs your attention" never gets visually confused with "click here to proceed."

## Copywriting Contract

**Funnel CTA sequence** (each is its own primary button, one visible at a time as the user
progresses):

| Step | Button label |
|------|-------------|
| Paste tab, ready to submit | Preview deck |
| URL tab, ready to submit | Import from URL |
| Preview resolved, ready to move on | Continue to commanders |
| Commander(s) selected, ready to finish | Start my table |

| Element | Copy |
|---------|------|
| Primary CTA (final conversion) | **Start my table** — appears once a legal commander is selected and no blocking errors remain; this is the button that calls `createGame`. |
| Empty state heading (deck import, before any input) | Paste your decklist |
| Empty state body | "Paste a list from any format you already use, or drop in a public deck URL below. We'll check every card and get you to commander selection." |
| Empty state heading (no legal commander detected) | No legal commander detected yet |
| Empty state body | "None of your parsed cards can legally be a Commander. Search for one manually, or check your list for a commander-eligible creature or planeswalker." |
| Error state — provider down (`provider_unavailable`) | "We can't reach that deck link right now." + "Paste your decklist instead — it takes about 10 seconds." → affordance button: **Paste instead** |
| Error state — preview/unresolved entries (`preview_error`) | "We couldn't fully read a few cards." + "Fix the highlighted entries below, then continue — your original paste is untouched." → affordance: **Fix these cards** (inline, per row) |
| Error state — guest-session error (`guest_session_error`) | "We couldn't set up your seat at the table." + "Nothing you entered was lost. Try again in a moment." → affordance button: **Try again** |
| Error state — create error (`create_error`) | "We couldn't create your table." + "Your deck and commander picks are still here — try again." → affordance button: **Try again** |
| Mobile heads-up notice (D-2.11, static banner, <768px only) | "This board is built for tablets and larger. You can finish importing your deck here — the board itself may feel tight on a phone." |
| Display name field placeholder | "Optional — skip it and we'll give you a name like 'Brave Sliver'." |
| Destructive confirmation | **Not applicable this phase** — no destructive action exists in scope. If a future "start over / clear pasted deck" action is added, it must confirm before clearing (`sessionStorage` draft is otherwise the only thing protecting an unsaved 100-card paste). |

Each of the four error-state rows carries a stable, server-owned, machine-readable error code
per D-2.13 (`provider_unavailable`, `preview_error`, `guest_session_error`, `create_error` —
exact names are the planner's/executor's to finalize against the server contract, but the
**one-code-per-class, one-copy-per-code, one-affordance-per-code** shape above is locked).
Never render raw GraphQL, SQL, or provider output in any of these four states.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many /
> long-text). Copy for empty/error states lives in `## Copywriting Contract` above and is
> referenced here, not restated.

Applicable state considerations resolved: 21 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | DeckImportPanel (form) | ✅ covered | Renders the "Paste your decklist" empty-state copy (see Copywriting Contract) before any paste/URL text is entered. |
| empty | CommanderReview (list-collection) | ✅ covered | Renders the "No legal commander detected yet" empty-state copy when `CommanderCandidates` is empty after a successful preview. |
| loading | DeckImportPanel (form) | ✅ covered | Inline spinner + "Checking your deck…" body text while `previewDeck` is in flight; submit button disabled for the duration. |
| loading | CommanderReview / unresolved-card list | 🧪 backstop | Candidates and suggestions arrive synchronously in the same `previewDeck` response (Phase 1: computed eagerly) — no separate loading UI is expected to exist for these two lists. Verify by asserting no loading-spinner markup is reachable for `CommanderReview`/unresolved-list independent of the panel-level loading state. |
| error | DeckImportPanel (form) — provider down | ✅ covered | `provider_unavailable` copy + "Paste instead" affordance (Copywriting Contract). |
| error | DeckImportPanel (form) — preview error | ✅ covered | `preview_error` copy + "Fix these cards" affordance (Copywriting Contract). |
| error | QuickStartView (nav/flow) — guest-session error | ✅ covered | `guest_session_error` copy + "Try again" affordance (Copywriting Contract). |
| error | QuickStartView (nav/flow) — create error | ✅ covered | `create_error` copy + "Try again" affordance (Copywriting Contract). |
| error | unresolved-card list, commander list (own error state) | ✅ covered | Dismissed by design — errors bubble to the panel-level error state above; no separate per-list error UI exists. |
| populated | DeckImportPanel preview totals | ✅ covered | Totals line pattern, e.g. "97 of 100 cards ready · 3 need a quick look," shown once `previewDeck` resolves. |
| populated | unresolved-card list | ✅ covered | Each unresolved row shows the original typed text, up to 3 suggestion chips (nearest match always shown per Phase 1 D-03, even below the resolution cutoff), plus a manual "type card name" fallback and a "remove this line" option. |
| populated | CommanderReview list | ✅ covered | Up to 3 detected commander candidates surfaced (Phase 1 product decision); manual search available beyond the top 3 via the existing typeahead pattern reused from `FormCreateGame.vue`. |
| partial | DeckImportPanel (warnings but `CanContinue: true`) | ✅ covered | Non-blocking banner ("X cards need a look") with Continue enabled; blocking errors instead disable Continue until resolved. |
| partial | CommanderReview (partner/background pairing incomplete or invalid) | ✅ covered | Reuses `partnerConstraintMessage` from `commanderPartner.ts` for inline validation text; Continue disabled until a single legal commander or a valid partner/background pair is selected. |
| partial | Display name field | ✅ covered | Dismissed — single optional text field has no partial-fill state distinct from empty; omission is itself a valid, expected terminal state (generates a guest name). |
| overflow | unresolved-card list (many unresolved rows) | 🧪 backstop | Capped-height scrollable list, reusing the existing `.typeahead` pattern (`max-height: 200px; overflow: auto`) rather than growing the page indefinitely. Verify by asserting a max-height/overflow rule exists on the unresolved-list container at both breakpoints. |
| overflow | CommanderReview (many legendary-creature candidates, e.g. a "commander matters" pile) | 🧪 backstop | Same capped-scroll treatment as the unresolved-card list, plus a "search all cards" manual fallback. Verify the same way. |
| zero-one-many | unresolved-card list | ✅ covered | 0 → section hidden entirely; 1–3 suggestions per row always render as a non-empty chip set (Phase 1 guarantees at least the nearest match); wrapping chip layout reads correctly at 1 and at 3. |
| zero-one-many | CommanderReview | ✅ covered | 0 → empty state above; 1 → single-commander happy path, no partner UI shown; many → up to 2 selected (partner/background) plus up to 3 suggestions each, wrapping chip grid. |
| long-text | unresolved-card / commander chip text (long card names) | ✅ covered | Truncate with ellipsis + `title` tooltip on hover, matching the existing `.stack-name` overflow-ellipsis pattern in `BoardView.vue`; chips wrap via `flex-wrap: wrap` per the existing `.chips` class. |
| long-text | Display name field | ✅ covered | Client `maxlength="64"` (mirrors the existing game-name field's bound); render sites apply the same truncate-with-tooltip treatment as above once rendered via `display_name ?? username`. |
| long-text | Mobile heads-up notice | ✅ covered | Copy is fixed and short (one sentence, ~140 characters) — no truncation logic needed; do not let this banner grow to more than two lines at 320px width. |
