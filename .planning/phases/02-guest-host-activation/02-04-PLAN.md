<decisions>
- **DEC-K — `game_created` needs a session identifier, so `InputCreateGame` gains an optional
  `SessionID`.** The server has no other way to learn the browser session that a conversion belongs
  to: the JWT carries a user, not a session, and `trackProductEvent` cannot supply it because
  `game_created` is authoritative and a client submission is refused by design. The field is
  additive and optional, so no existing caller breaks; both in-app call sites (`QuickStartView.vue`
  and `FormCreateGame.vue`) always send it, and `CreateGame` skips the event write rather than
  emitting a guaranteed-rejected one when it is absent.
- **DEC-L — the event write happens after the game is persisted, never before.** A conversion
  recorded for a game that failed to save would inflate the numerator of the exact activation rate
  this milestone is measured on. The failure exit observes the metric with a failure outcome and
  writes no product event.
</decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-supplied `SessionID` -> `product_events` | An unauthenticated, caller-chosen string persisted on a conversion row |
| client `trackProductEvent` -> authoritative event names | The boundary criterion 5 protects: a client must not be able to write a conversion |
| Vue Router guard -> every protected route | Adding a public route must not weaken an existing guard |
| server metrics -> Prometheus labels | Any caller-derived value in a label position is a cardinality bomb |
