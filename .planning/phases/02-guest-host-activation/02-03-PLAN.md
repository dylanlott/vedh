<objective>
Build the one deck-import surface the whole product now shares, the commander-review component that
sits behind it, and the failure contract that keeps a visitor's work on screen when something breaks.

Purpose: today `FormCreateGame.vue` and `JoinGameView.vue` carry a literally duplicated textarea
labelled "Decklist (CSV: quantity,name per line)" — the exact format Phase 1's six-syntax parser
superseded. Both call sites are actively telling users the wrong thing. This plan replaces them with
one component that speaks the real contract, and gives `/play` the review, recovery, and responsive
behavior the UI design contract locks down.

Output: `DeckImportPanel.vue`, `CommanderReview.vue`, the mobile heads-up notice, the shared
breakpoint, the client error-code map, sessionStorage draft persistence, and three call sites now
served by one component.

Delivers REQ-ACT-004; completes REQ-A2 and advances REQ-A7.
</objective>

- **DEC-H — `/play` runs alongside the existing flows, and the landing CTA is not touched.**
  REQ-ACT-004 requires two things and only two: replace the duplicated deck entry in
  `FormCreateGame.vue` and `JoinGameView.vue`, and keep the authenticated create flow usable during
  rollout. Both are satisfied by extracting one component and swapping it into three call sites.
  Rewriting `LandingView.vue`'s call-to-action is REQ-ACT-011's own text ("`/play` as primary CTA

  scope, not satisfying this one.
- **DEC-I — `CommanderReview.vue` consumes `commanderPartner.ts` as-is.** No extension, no
  supersession. The partner and background rules it already encodes are the rules; re-encoding them
  in a new component is how the two drift.
- **DEC-J — `DeckImportPanel.vue` takes no slots and owns no surrounding chrome.** Its props are
  exactly what `InputDeckImport` accepts plus a persistence key; game name, deck size and format stay
  with whichever parent owns them. This bounds the component's responsibility and removes the
  slot-customization question entirely.
</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor keystrokes -> `previewDeck` | Untrusted free text (up to a full decklist) leaving the browser |
| server error -> rendered failure copy | The boundary criterion 4 protects: no raw GraphQL, SQL, or provider text may cross into the DOM |
| visitor-typed display name -> DOM | Free-form untrusted text rendered back to the same visitor and, later, to other players |
| activation draft -> `sessionStorage` | A full decklist and a display name written to browser storage on a possibly shared machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-16 | Information Disclosure | rendered failure copy | high | mitigate | `resolveActivationError` returns entries only from a frozen record and is structurally incapable of returning the underlying error message; asserted directly by `activationErrors.spec.ts`. Unknown and missing codes fall back to a generic entry rather than the raw error. |
| T-02-17 | Tampering | display name and card names rendered in chips, tooltips and the totals card | medium | mitigate | Every render goes through Vue's default text interpolation, which auto-escapes; the `title` attribute is bound, not interpolated into raw markup; no raw-HTML directive appears anywhere in the new components, asserted by a grep gate. |
| T-02-18 | Information Disclosure | activation draft on a shared machine | medium | mitigate | The draft lives in `sessionStorage` (dies with the tab) rather than `localStorage`, is cleared explicitly on successful game creation, and the module is asserted to touch no `localStorage`. Accepted residual: a tab left open on a shared machine retains the paste, which D-2.12 chose deliberately over losing a 100-card paste to a refresh. |
| T-02-19 | Denial of Service | rapid repeated preview submissions | medium | mitigate | The submit control is disabled while a request is in flight, and out-of-order responses are discarded by sequence number; the server-side `SurfaceDeckImport` limiter shipped in Phase 1 remains the authoritative bound. |
| T-02-20 | Tampering | a suggestion silently replacing a card the visitor typed | medium | mitigate | Suggestions are applied on explicit click only; re-previewing never auto-applies one and never clears an applied correction. Carried as a minted prohibition, not merely a test. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan installs no packages. No icon library, no component registry, no responsive framework is added; `app/package.json` is untouched. |
</threat_model>
