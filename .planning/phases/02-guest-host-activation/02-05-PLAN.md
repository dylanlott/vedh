<decisions>
- **DEC-M — the display name is written onto the game payload at create and join time, not joined at
  read time.** Games are stored as one JSONB `payload`; a read-time join would add a per-player
  lookup to every game read and every subscription push. There is no rename feature anywhere in the
  product (02-CONTEXT.md § Deferred Ideas records this explicitly), so a write-time snapshot cannot
  go stale, and `claimGuestAccount` leaves `display_name` untouched by design.
- **DEC-N — one helper, not a per-file inline expression.** `displayNameOf` is the single seam the
  assumption-delta decision promotes to primary. An inline `?? ` at eight call sites is eight places
  for the next person to forget, and gives the invariant test nothing to assert against.
</decisions>

| Boundary | Description |

| game payload -> deserialization | Legacy payloads written before this phase must still parse |
