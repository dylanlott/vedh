<decisions>
- **DEC-E — error codes travel as GraphQL error extensions, not as a message prefix.** A prefix
  convention is parseable by accident and leaks into any surface that renders `error.message`.
  `*gqlerror.Error{Message: <product copy>, Extensions: {"code": <class>}}` keeps the machine field
  and the human field separate, needs no custom presenter, and cannot be confused with the flat
  `Warnings`/`BlockingErrors` strings the Phase 1 parser already returns (which are already
  user-safe and are deliberately NOT re-typed here — D-2.13's codes cover transport and flow
  failures only).
- **DEC-F — the guest credential is not rotated on re-issue.** Rotation would invalidate the
  credential held by a second tab of the same browser mid-funnel. The credential's blast radius is
  already bounded by the fact that it only mints tokens for a guest row, and claiming clears it
  outright.
- **DEC-G — the cleanup guard is deliberately stricter than the requirement.** REQ-ACT-005 says
  "unreferenced expired guests" and criterion 3 says "never deletes one referenced by an active
  game". Because games are stored as a single JSONB `payload` (there is no foreign key to `users`),
  the guard refuses to delete a guest whose uuid or username appears in ANY `games` row, finished or
  not. Stricter than asked, fails safe, and needs no assumption about the payload's internal shape.
</decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> `refreshGuestSession` | Unauthenticated bearer-credential exchange; deliberately outside `requireAuth` |
| anonymous browser -> `login` | Pre-existing password endpoint, now reachable for rows that are guests |
| guest JWT -> `claimGuestAccount` | Authenticated but privilege-changing: turns a guest row into a real account |
| operator -> `CleanupExpiredGuests` | Destructive, manually invoked, no scheduler |
| server -> browser (error copy) | Product-language messages only; no SQL, driver, or provider text may cross |
