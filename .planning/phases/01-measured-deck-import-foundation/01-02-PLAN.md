  <action>
Rewrite `Parse` in `pkg/deckimport/scanner.go` as an explicit, ordered per-line rule set. Rule
order is the whole design; implement it in exactly this sequence and name each rule in a comment so
a reviewer can check the order rather than infer it.

1. Enforce `MaxDecklistBytes` and `MaxDecklistLines` before scanning; on breach emit one blocking
   error and return.
2. Split lines on line-feed and strip a trailing carriage return so carriage-return, line-feed, and
   the pair all terminate a line identically. Count every nonblank line into `NonBlankLines`.
   A line that is empty or whitespace-only is skipped silently — the only rows permitted to vanish.
3. Comment and section-header check, **anchored at the start of the line only**. A line beginning
   with a double slash, a hash followed by a space, or one of the header words handled in task 2 is
   a comment or header and never an entry. The start-of-line anchor is load-bearing, because a
   double slash also separates the two faces of a double-faced card, and the repo's own
   `test/decklists/jarad.csv` ships three of those unquoted. A rule that strips everything after a
   double slash anywhere on the line silently shortens a real card the project already uses as
   test data.
4. Quantity extraction: consume leading ASCII digits; then consume at most one `x` or `X`; then
   consume at most one comma; then consume any run of spaces and tabs. This single ordered
   consumption is what makes `1 `, `1x `, `1,`, and `1, ` all equivalent prefixes. Absent leading
   digits, default the quantity to 1 and treat the whole line as a name. A quantity that parses to
   zero or a negative number, or that exceeds a documented maximum, emits a warning attached to
   that source line and produces no entry — never a whole-deck failure. Today every error path in
   `createLibraryFromDecklist` returns nil plus an error, which is precisely the behaviour this
   replaces.
5. Quoted-name check: if the remainder starts with a double quote, read to the matching closing
   quote and take that span verbatim as the name. This is the only place CSV quoting semantics
   apply, and it is what makes the quoted Atraxa form work.
6. Trailing-annotation extraction on the *unquoted* remainder, right to left, in this order: hash
   tags; a trailing backtick-delimited category; a trailing bracketed category; a trailing bare
   alphanumeric collector number that follows a parenthesised group; a trailing parenthesised set
   group. Record each into `SetCode`, `CollectorNumber`, `Category`. Preserve the set code's letter
   case exactly as written — the corpus asserts both `C21` and `c21` round-trip unchanged, because
   the printing-disambiguation lookup in plan 01-04 lower-cases at query time rather than at parse
   time.
7. The name is everything that remains, trimmed. Commas inside it are ordinary characters. This is
   the rule that fixes both unquoted Atraxa forms: after rule 4 consumes the quantity and its one
   separator, the rest of the line is the whole name including its internal comma.
8. Emit the entry with its `SourceLine` (1-based) and `RawLine`.

Assert the accounting invariant in code, not only in tests: before returning, compare
`len(Entries) + len(Warnings) + len(BlockingErrors) + DroppedSectionRows` against `NonBlankLines`
and, on mismatch, append a blocking error naming the discrepancy. A parser that loses a row must
say so rather than return a plausible-looking deck.

Name comparison and lower-casing throughout this package use ASCII lower-casing with no Unicode
normalization: two names that render alike but differ in code points are different names, and this
is stated in a doc comment on `Parse` so the boundary is documented rather than discovered.

The package continues to log nothing. Warnings are return values.
