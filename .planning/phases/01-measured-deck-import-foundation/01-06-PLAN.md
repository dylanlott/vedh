Create `server/deck_providers.go` with two independent hooks whose responsibilities do not overlap.
The split is what makes each one separately testable and is why neither alone is sufficient.

**Layer one — the dial-control hook owns address and port policy.** Declare two ordered slices of
parsed address prefixes, one for each address family, transcribing the registry-derived deny list in
the research pattern. Declare them in a fixed order and document that the first matching prefix is the
one named in a refusal, so an address inside two prefixes produces a deterministic reason. The hook
signature is the context-aware dial-control form, which receives the network, the already-resolved
literal address, and the raw connection.

The hook refuses anything that is not a TCP network; splits the host and port with the standard helper
so the bracketed IPv6 form is handled; refuses any port other than the secure one, enforcing the
scheme restriction at the socket layer as well as at the URL layer; parses the host as an address
literal and refuses anything unparseable; unmaps an IPv4-mapped IPv6 address before any prefix check,
which is what closes the class of bypass where the metadata address is written in mapped form; refuses
loopback, unspecified, multicast and link-local addresses through the standard predicates; and then
walks the family's prefix slice refusing the first containment.

Do not use the standard library's global-unicast predicate as the gate. Its own source comment states
that private and unique-local addresses are still considered global unicast, so it is not merely
insufficient here — it is misleading. The private-address predicate alone is also insufficient: it
covers one legacy range set and the unique-local block, and catches none of the shared-address,
protocol-assignment, or benchmarking ranges the deny list names, which is where the metadata address
has neighbours.

Validating inside the dial-control hook rather than by resolving the name and checking the result
first is the point of the whole design. Resolve-then-dial is vulnerable by construction: a
caller-controlled name server with a short record lifetime can answer with a public address for the
validating lookup and the target address for the connecting lookup. The hook runs after resolution and
before the connect call, receiving the literal that will actually be dialled, so there is no window.

**Layer two — the redirect hook owns scheme and host policy.** Set the redirect callback to refuse
when the hop count reaches the bound, refuse any scheme other than the secure one, and refuse any host
whose lower-cased value is not an exact member of the allowlist. Exact equality only: never a suffix
or prefix comparison, because a host that merely ends with an allowlisted name is a different host and
matching it is the bypass. Compare the ASCII form the URL parser returns, lower-cased, and perform no
decoding step before comparing, so an internationalized or percent-encoded host that would decode to
an allowlisted name is refused rather than accepted. Returning an error from this callback is a genuine
hard stop, not a soft signal.

**Client construction.** Build the dialer with a three-second connect timeout and the control hook.
Build the transport with the dialer's context-aware dial function, a three-second handshake timeout,
keep-alives disabled, and the proxy field set explicitly to nil with a comment stating why. The
environment-derived proxy resolver — which the widely-copied reference snippet for this pattern
includes — silently disables the entire address control, because with a proxy configured the dialer
connects to the proxy and the hook validates the proxy's address while the real destination travels in
a tunnel request the hook never sees. Every control would pass its tests and the client could still
reach the metadata address. Set the client's overall timeout to eight seconds: that field is
documented to cover connection time, all redirects, and the response body read, which is exactly the
locked total budget and is what stops a slowly-trickled body from hanging far past it. Express every
timeout as an integer duration so no rounding can widen a budget.

**Body cap.** Read through a limited reader bounded at one mebibyte plus one byte and compare the
counted length; a length over the cap fails closed. Never consult the declared content length: it is a
header the remote controls and may be absent entirely under chunked transfer, so only a counted read
is a control.

Add the host allowlist as an envconfig field on `Conf` named `DECK_PROVIDER_ALLOWED_HOSTS`, defaulting
to empty, parsed into a lower-cased set. An empty allowlist means nothing is fetchable, which is the
correct default.

Add two collectors to `pkg/telemetry/metrics.go`: a counter `vedh_deck_provider_fetch_total` and a
histogram `vedh_deck_provider_fetch_duration_seconds`, both labelled by provider and outcome, with
histogram boundaries placed exactly at three and eight seconds so a pile-up at the connect timeout and
one at the total timeout are separately readable — the default bucket set has neither boundary and
cannot show that. Extend the metrics tests to cover both.

**Tests** in `server/deck_providers_test.go`, none of which touches the network:
`TestSafeControl_DeniedAddresses` calls the control hook directly as a table test over the metadata
address, a loopback address, a shared-address-space address, the metadata address written as an
IPv4-mapped IPv6 literal, a protocol-assignment address, a benchmarking address, a public address on
the wrong port, a public address on a non-TCP network, and one public address on the correct port that
must be allowed. No socket is opened at all, so this is fast, hermetic, and exhaustive.
`TestSafeControl_ReportsFirstMatchingPrefix` asserts the refusal names the first prefix in declared
order for an address inside two.
`TestSafeClient_HostAndRedirect` uses loopback test servers: one allowlisted server for the positive
case; an allowlisted host differing only in letter case, accepted; a host containing an allowlisted
host as a suffix, refused; a first server redirecting to a second that is not allowlisted, asserting
both the error and that the second server's handler was never invoked; a redirect to a non-secure
scheme, refused; and a chain long enough to trip the hop bound.
`TestSafeClient_RejectsBeforeResolution` asserts an empty host and a non-secure scheme are refused with
no name resolution attempted, using a resolver stub that records whether it was called.
`TestSafeClient_RebindingFailsClosed` points a custom resolver at an in-process stub answering with a
public address first and a loopback address second, and asserts the second connection is refused by
the control hook — proving the hook is actually wired into the client rather than merely correct in
isolation.
`TestSafeClient_BodyCap` uses two handlers: one streaming exactly the cap, accepted; one streaming the
cap plus one byte, refused; and one declaring a tiny content length while sending two mebibytes,
refused — that last is the case that catches an implementation trusting the header.
`TestSafeClient_Timeouts` uses handlers that sleep past each budget, with the client's timeouts
parameterised down so the test itself stays fast, asserting the elapsed time is bounded and the error
is a timeout.
`TestSafeClient_ZeroByteBodyIsProviderError` asserts an empty response body yields a normalized
provider error rather than an empty deck.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → public resolvers | `previewDeck` and `trackProductEvent` accept traffic with no identity; request volume is attacker-chosen |
| server process → arbitrary outbound host | A deck URL is caller-supplied; this is the only place this codebase makes an outbound request on a caller's behalf |
| caller-controlled name server → dial | Name resolution for a caller-supplied host is answered by infrastructure the caller may control |
| deployment environment → process configuration | The kill switch and host allowlist arrive as environment variables |
