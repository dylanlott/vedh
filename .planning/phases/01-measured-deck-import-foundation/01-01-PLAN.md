**1. Migration `product_events` — four files, two directories.**
Create `persistence/migrations/20260804120000_product_events.up.sql` defining table
`product_events` with columns `id BIGSERIAL PRIMARY KEY`, `event_name TEXT NOT NULL`,
`session_id TEXT NOT NULL`, `user_id VARCHAR(255)`, `game_id TEXT`, `role TEXT`,
`source TEXT`, `outcome TEXT`, `duration_ms INTEGER`,
`metadata JSONB NOT NULL DEFAULT '{}'::jsonb`, `occurred_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
`user_id` is `VARCHAR(255)` because `users.uuid` is `VARCHAR(255)`, not a uuid column;
`game_id` is `TEXT` because `games.id` is `TEXT`. Declare **no foreign keys at all** — ACT-005's
guest cleanup deletes user rows in Phase 2, and an FK would either block that cleanup or
cascade away the funnel history the 7-day-claim metric depends on, and would make a write
fail when the referenced row is gone, which D-17 forbids.
Add `product_events_name_time_idx` on `(event_name, occurred_at DESC)` and
`product_events_session_time_idx` on `(session_id, occurred_at)`.
Add the dedup index `product_events_authoritative_once` as a UNIQUE index on
`(event_name, COALESCE(game_id, ''), COALESCE(user_id, ''), session_id)` with a
`WHERE event_name IN (...)` predicate naming exactly `game_created`, `player_joined`,
`guest_session_created`, `account_claimed`. The `COALESCE` wrappers are load-bearing:
PostgreSQL 14 has no `UNIQUE NULLS NOT DISTINCT` (PG15 only), and both the dev compose file
and the smoke CI service pin `postgres:14`, so without them two rows with NULL game_id are
distinct and the index deduplicates nothing. The two `deck_import_*` events are deliberately
outside the predicate — a player may legitimately import several times.

the one exception, and it is a whitespace trim, not a normalization of the retained value.
